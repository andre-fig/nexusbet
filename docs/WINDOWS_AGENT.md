# Collector-agent neste Windows

O Windows 11 deste PC executa apenas Superbet, Blaze e EstrelaBet por HTTP. Bet365 e Betano exigem o `local-cdp` suportado no macOS e ficam desabilitados aqui. O agent envia scopes por HTTPS ao server no Railway; não recebe `DATABASE_URL` e não acessa PostgreSQL. O token e a outbox ficam em `%LOCALAPPDATA%\NexusBet`, fora do checkout. O server continua responsável pelas transações SQL.

`scripts/windows-agent-reconcile.ps1` consulta `main` a cada execução. Se o SHA mudou, clona a nova versão para uma release isolada com `core.autocrlf=false` (o Git da conta SYSTEM tem checkout CRLF por padrão e isso faz o Prettier rejeitar todos os arquivos), executa `npm ci`, `typecheck`, `format:check`, `build` e `npm test`, solicita shutdown do agent atual por marker e troca `current.txt`. Uma falha de GitHub ou de validação conserva a versão anterior. O mesmo script reinicia o agent caso o processo tenha saído. Falhas de internet durante a coleta são tratadas pela outbox e pelo retry do próprio agent; quando GitHub voltar, o próximo ciclo atualiza.

A tarefa `NexusBetCollectorAgent` roda a cada minuto e no login da conta Windows. Para iniciar também antes do login, `scripts/install-windows-agent-boot.ps1` registra `NexusBetCollectorAgentBoot` sob `SYSTEM`, com triggers de startup e a cada minuto, e desabilita a tarefa de usuário. A instalação exige PowerShell elevado; o script reabilita a tarefa de usuário se o registro falhar. Ambas usam `-MultipleInstances IgnoreNew`, e o supervisor usa um mutex. Nunca deixe as duas tarefas ativas ao mesmo tempo.

`agent.json`, `outbox`, `releases`, `current.txt`, `failed.txt`, `agent.pid` e logs ficam em `%LOCALAPPDATA%\NexusBet` da conta original. A tarefa SYSTEM recebe esse caminho e o caminho absoluto do Node 24 como argumentos; não usa `%LOCALAPPDATA%` de SYSTEM. O supervisor é copiado para esse diretório, de forma que a própria atualização do checkout não altere um script em execução. Depois de mudar o supervisor no repositório, copie a nova versão e valide a tarefa antes de considerá-la ativa. A release só é elegível com `.agent-verified` contendo seu SHA, gravado **após** todos os checks; um `dist` parcial não autoriza deploy. Uma release que falhe nos checks ou saia durante startup é registrada em `failed.txt`; a próxima mudança de SHA na `main` libera nova tentativa, conservando a release anterior. `scripts/windows-agent-rollback.ps1` restaura uma release validada por SHA quando uma troca já ocorreu; exige PowerShell elevado para parar um agent SYSTEM.

A tarefa de usuário inicia **após o login**. A tarefa SYSTEM pode iniciar antes do login, mas precisa de validação após um reboot real. O runtime atual de três providers HTTP não exige sessão gráfica. Não confunda registro de tarefa com validação de reboot ou recuperação de uma falha de internet.

Para inspecionar localmente, use `Get-ScheduledTask -TaskName NexusBetCollectorAgent`, o log `%LOCALAPPDATA%\NexusBet\logs\supervisor.log`, os logs `agent-*.log` e o endpoint autenticado `GET /internal/agents`. Não imprima `agent.json` ou variáveis do Railway em logs. A outbox mantém mensagens pendentes durante falhas de rede, sujeita aos limites de retenção descritos em [Runtimes](RUNTIMES.md). No Windows, a gravação da mensagem faz `fsync` do arquivo antes do rename; o sistema não permite `fsync` do diretório como no macOS/Linux.
